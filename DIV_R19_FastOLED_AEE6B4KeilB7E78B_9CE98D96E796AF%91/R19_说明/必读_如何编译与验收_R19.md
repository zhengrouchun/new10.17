# DIV三工况：R19 源码同步诊断版（未经过 Keil+Proteus 联合仿真验收）

## 文件来源与范围
- 依据用户上传《代码 (3).zip》对应STM32F103C8T6 HAL工程整理。本包不包含 Proteus .pdsprj/.dsn 电路文件，无法改变仿真中真实电阻、开关、电压表、网表或接线。
- 仅修复/增强固件的“不同轮次结果混在一起、OLED显示上一轮、上电 OLED 延迟、调试日志无法关联同一轮测量”等问题。
- **未**更改工况判别阈值、ADC参考电压3300mV、PA0=VB/PA1=VA的对应、PB12/PB13电源控制极性、20ms按键消抖等业务基础逻辑。
- 并不保证电路原本错误的网络自动成为正确工况：R1=10kΩ却测得VB=588mV/VA=886mV，说明实际有效网络并非文件中理想的10k/10k/2k分压结构，需要检查真实网表，尤其是隐藏并联、测量节点、R1/R8同时存在、SW2/SW5和供电线误接。

## 与R18的差异
1. `Inc/div_app_types.h`: 增加 cycle_id/sample_tick_ms，跟踪同一轮测量，原有数据字段保留。
2. `Src/div_measurement.c`: TEST_SAMPLE与最终STATE报告附带一致的 ID 和 SAMPLE_T；每次开始通知屏幕撤销旧工况，防止屏幕继续冒充当前结果。测量结果仍直接来自 ADC，**不**拿理论值强行替代。
3. `Src/div_display.c`, `Inc/div_display.h`: 检测期间显示DIV TESTING，STOP状态VA/VB显示NA STOPPED（以前的数值不是断电后的实时电压）。HB日志带当前CYCLE。
4. `Src/main.c`: OLED初始化提前到首次耗时检测之前，避免开机必须先等约6秒才有任何画面。
5. `Src/div_control.c`: 统一FW版本为DIV_SYNC_R19，消除一份固件同时显示R16/R18版本号造成的误解。

## 编译注意——**必须重新生成HEX**
此环境没有ARMCC/Keil与Proteus，**没有生成任何新的R19 HEX，也没有验证实际Proteus电路效果**。本工程包故意未在加载路径保留旧 HEX，防止把R18误认为新固件。
1. 用Keil MDK5打开 `代码/MDK-ARM/ADC_CubeMX_Keil.uvprojx`。
2. `Project → Rebuild all target files`，确认 `0 Error(s)`，勾选生成HEX（当前配置Create HEX File=1）。
3. 查看 `代码/MDK-ARM/ADC_CubeMX_Keil.hex` 的新修改时间。
4. 在Proteus U1的Program File中**重新选择**此新HEX。Proteus设计文件没有包含在本次上传ZIP里；不要继续使用旧绝对路径或旧HEX。
5. Proteus Virtual Terminal按当前代码设 **57600，8N1**（源码`usart.c`和说明文档均为57600，不是早期115200）。
6. 重启仿真，串口开头必须打印 `FW=DIV_SYNC_R19`。如不是这个字符串，说明仍在加载旧HEX。
7. CubeMX重新生成代码可能覆盖`main.c/gpio.c/adc.c`中的自定义内容和项目结构。验收中不建议重新Generate Code；确需再生成，先备份并对比差异。

## 测试重点：只有同一时刻的量才能比较
- 找到本轮串口 `TEST_SAMPLE ID=1 SAMPLE_T=... VB_MV=... VA_MV=... TEST_GPIO=HIGH RUN_GPIO=LOW`；这个读数代表**1V测试阶段**。
- R19在1V采样后约5秒内继续维持测试电源，暂停Proteus，查看DIV_VA、DIV_VB电压表，并和相同 ID 的TEST_SAMPLE及OLED结果比较。约5秒后自动切换最终供电，**不得**再拿切换后3V实时电压表与旧1V样本比较。
- `STATE=... ID=1` 和 `TEST_SAMPLE ID=1` 是同一轮检测；之后RETEST产生ID=2、3、4……。
- OLED的第四行T/R显示GPIO命令，不自动证明负载端实际已经收到1V或3V，必须额外用电压表验证 K_DIV_TEST/K_DIV_RUN 输出和RS左端。

## 先验收三工况（均在**1V测试阶段**比对）
| 工况 | 元件与开关 | 理论VA/VB | 期望OLED | 检测结束后 |
|---|---|---|---|---|
| DIV0 正常 | RS2k R1=10k R2=10k；SW6、SW4闭合，SW5、SW2断开 | VA909.1mV / VB454.5mV | DIV0 NORMAL | T OFF, R ON |
| DIV1 R1断路 | SW6断开、SW4闭合，SW5、SW2断开；R1=10k | VA1000mV / VB0mV | DIV1 R1 OPEN | T OFF, R OFF |
| DIV6 R1=20k | SW6、SW4闭合，SW5、SW2断开；R1=20k | VA937.5mV / VB312.5mV | DIV6 R1=20K | T OFF, R OFF |

每次先松开STOP，调整故障开关，再按一次RETEST，检查`RETEST_ACCEPTED`，`DETECTION_START`，`TEST_SAMPLE ID=...`，最终`STATE=... ID=...`和OLED。若硬件STOP已生效但未出现新ID，先检查PA4/EXTI4事件与停止锁存。每个工况建议重新上电再做一次，以排除开关历史状态影响。

## 若仍然10k对应DIV5，优先做这个“电路排障”
1. 在Proteus中在TEST阶段同时记录：RS左端电压（须约1V），VA（RS和R1之间），VB（R1和R2之间），R2下端（须0V）。
2. 核对R1=10k**只有一个**实际导电支路。如果有第二只10k（例如替换后的R8、旧R1或SW5旁路）并联，等效阻值可能是5k，实际VB≈588mV、VA≈882mV，会被正确判为DIV5。
3. 不要把TR的控制电平3.3V当成负载测试电压1V/3V。检查 VSWITCH 电控端与主回路，特别是控制端在PB12=3.3V时确实导通、PB12=0V时确实断开。
4. DIV1需确认断开的是RS与R1之间串联通道(SW6)，且保留R2下端接地；电压应VA≈1V VB≈0V。若实测不是，先排接线而非修改判别阈值。
5. 如果真实Proteus节点是455/909，但同一ID的TEST_SAMPLE不是，则再查PA0/PA1网标、ADC通道与取样时序；按阶段而不是照着OLED结果猜电路。
